# 0002: PostgreSQL as source of truth, PGlite for tests and desktop, Drizzle ORM

## Context

The system needs a task queue safe under concurrent workers, an outbox for domain events and a transactional audit log. Tests and the future desktop app must not require a separate database server.

## Decision

PostgreSQL 17 is the single source of truth. Development uses `docker compose up db`. Tests use PGlite (Postgres in WASM, in-process), and the desktop app embeds PGlite with a data directory. Drizzle ORM with committed SQL migrations generated by drizzle-kit. The driver is chosen by config: `node-postgres` (`DATABASE_URL`) or PGlite (`PGLITE_DIR`, or in-memory). The queue uses `SELECT ... FOR UPDATE SKIP LOCKED`, and events go through a transactional outbox relayed with `pg_notify`.

## Consequences

- Real Postgres semantics in tests and CI without Docker.
- One dialect for all deployment modes.
- Code must stay within the feature set common to Postgres and PGlite.
- The in-process bus is needed in PGlite mode, where `pg_notify` across processes is not available.
