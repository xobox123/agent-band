# agent-band Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Control plane for AI coding agents: org, people and RBAC, personalised agents and groups, versioned policies, skills library, Jira-like task board, workers running Claude/Codex CLIs, usage limits, hash-chained audit trail, Lens-like web UI on localhost.

**Architecture:** Modular monolith (see spec "Architecture"). One Fastify app with modules `org, accounts, agents, policy, skills, tasks, runs, usage, audit, runner`, each with `domain/ app/ infra/ http/` layers and a public `index.ts`. PostgreSQL via Drizzle (node-postgres in dev/prod, PGlite in tests). Queue with `FOR UPDATE SKIP LOCKED`, transactional outbox + `pg_notify` for events, SSE to the browser. Roles `api | worker | all`.

**Tech Stack:** Node 22+, TypeScript strict ESM (run with tsx), Fastify 5, Drizzle ORM + drizzle-kit, PGlite, pg, zod, pino, Vitest, React 19 + Vite.

Spec: `docs/superpowers/specs/2026-10-06-agent-band-design.md`. Rules: `AGENTS.md`.

## Global Constraints

- Server binds `127.0.0.1`, port `AGENT_BAND_PORT` (default 4870).
- Every use case receives an `ActorContext` and calls `authorize()` before acting; every state change writes an audit event in the same transaction.
- Module boundary: a module never imports another module's `infra/` or reads its tables; only its `index.ts`.
- Tests use PGlite in memory with migrations applied; no real `claude`/`codex`, no paid APIs.
- Secrets never leave the server in HTTP responses or logs.
- `npm run format:check && npm run lint && npm run typecheck && npm test` must pass before each commit.
- Conventional commits, English, no AI attribution or Co-Authored-By lines. No em dashes anywhere.

### T3: Runner adapters (pure + process, no DB)

Follow the "Recorded CLI facts" below exactly. Fixtures exist in `apps/server/test/fixtures/` (do not regenerate).

**Recorded CLI facts**

- Claude `claude -p ... --output-format stream-json --verbose`: `rate_limit_event` with `rate_limit_info.{status, resetsAt (unix s), rateLimitType, unifiedWindows.{five_hour,seven_day}.{utilization 0..1, resetsAt}}`; `system/init` with `session_id`; `assistant.message.content[]` blocks `text|tool_use|thinking`; final `result` with `is_error`, `result`, `total_cost_usd`, `usage.{input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens}`. Count usage ONLY from `result`.
- Codex `codex exec --json`: `thread.started.thread_id`, `item.completed.item.{type: agent_message|reasoning|command_execution|..., text}`, `turn.completed.usage.{input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens}`, `error.message`, `turn.failed.error.message`. Rate limits only in `$CODEX_HOME/sessions/**/rollout-*-<thread_id>.jsonl`, last line with `payload.type == "token_count"` and `payload.rate_limits.{primary,secondary}.{used_percent, window_minutes, resets_at}` (primary = 5h, secondary = weekly).

**Produces** (in `apps/server/src/runner/`, types in `@agent-band/contracts` `runner.ts`):

```ts
  | { kind: 'usage'; inputTokens: number; outputTokens: number; cachedTokens: number; costUsd?: number }

```

Rules:

- Claude args: `-p prompt --output-format stream-json --verbose --permission-mode {plan|acceptEdits|bypassPermissions}` + `--model`, `--allowedTools a,b`, `--disallowedTools a,b`, `--append-system-prompt`, `--plugin-dir <skillsDir>` when set.
- Claude parse: rate_limit windows `five_hour -> 5h`, `seven_day -> weekly`, `usedPercent = round(utilization*100, 1)`, ISO from unix seconds, `limitReached = status === 'rejected'`; init -> session; assistant text (non-empty) and tool_use -> events, thinking skipped; result -> usage `{ inputTokens: input + cache_creation, outputTokens, cachedTokens: cache_read, costUsd }`, plus error when `is_error`, plus `rate_limit{limitReached:true, windows:[], resetsAt:null}` when the error text matches `/usage limit|rate limit|limit reached/i`.
- Codex args: `exec --json --skip-git-repo-check` + `-s read-only` | `-s workspace-write` | `-s danger-full-access` (codex 0.160 removed `--full-auto`; exec never asks for approval), `-m model`; prompt = `systemPrompt + "\n\n" + prompt` when systemPrompt; tools lists ignored.
- Codex parse: thread.started -> session; agent_message -> text; reasoning skipped; other item types -> tool `{name: item.type, input: item}`; turn.completed -> usage `{ inputTokens: input - cached, outputTokens: output + reasoning, cachedTokens: cached }`; error/turn.failed -> error (+ rate_limit on limit text).
- `spawnJsonLines`: stdin ignored; stdout lines parsed, a throwing parse becomes `stderr` event; stderr lines -> `stderr`; ENOENT -> single `error` `<cmd> not found in PATH`, `done.error` same; `cancel()` SIGTERM then SIGKILL after 5 s; onExit events appended.
- CodexAdapter captures the thread id from the session event and appends `readCodexRateLimits` result on exit.

**Tests:** fixture-driven parser tests with exact expected values (read numbers from the fixture files), args builders for every mode, `spawnJsonLines` with `process.execPath -e` scripts (stdout/stderr/bad json/exit code/missing binary/cancel/onExit), rollout reader with a temp CODEX_HOME, `runEnv`.

### T9: worker / dispatcher

`apps/server/src/roles/worker.ts`: loop `claim -> resolve candidates (agent | label | group) -> for each: getEffectivePolicy, getEffectiveSkills, evaluateRunStart (audit policy.decision), accountAvailability -> first ok wins; none ok but some only unavailable -> releaseTask; all denied -> task denied`. Start: materialise skills into `os.tmpdir()/agent-band/runs/<runId>/skills` (Claude: plugin layout `.claude-plugin/plugin.json` + `skills/<name>/...`; Codex: per ADR from T3 verification), build `RunSpec`, adapter by account provider, consume events (`appendRunEvent`, `agent.tool_use` audit per tool event, rate-limit windows to usage, block on limitReached), enforce `maxRunMinutes`, finish run + task, cleanup temp dir, publish events. Cancellation via outbox event `task.cancel_requested` handled by the worker owning the run. Concurrency per worker `AGENT_BAND_WORKER_SLOTS` (default 4). Graceful stop.
**Tests (FakeAdapter, PGlite):** happy path; label and group targeting; deny path with reasons; account limit release and block; cancellation; maxRunMinutes; two workers in parallel on one DB; tool_use audited with agent as actor; skills materialised and recorded on the run.
