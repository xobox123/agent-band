# API response details

## Provider account fields

`ProviderId` and `PROVIDER_IDS` in `packages/contracts` define the closed provider
list. `GET /providers` returns `accountFields` as JSON Schema generated by zod v4.
The web form supports a flat root `object` with `properties` and a `required`
array. Properties may be strings, string enums, numbers, integers, booleans, or
arrays of strings (entered as comma-separated lists). Enum values must be strings.
Nested objects, unions, references, conditional schemas and arrays of objects are
not supported. `$schema` and `additionalProperties: false` may be present.
Constraints such as `format`, `minLength`, `maxLength`, `maxItems` and refinements
are validated by the server; the form does not interpret all such constraints or
apply schema defaults. Secret values are separate write-only account fields.

## Effective policy

`rules[name]` contains the effective value, `setBy`, all explicit `contributors`,
and provider-specific `coverage` with scoped `coverageDetails`. `setBy` is the
last policy that changed the effective restriction, or the first explicit source
when its value equals the default. It is null for an implicit default. Merged
lists may require multiple contributors; `setBy` is not an override of those
contributors. `workDirs` values are intersected sets of roots.

Coverage reflects implemented adapters, not potential native CLI features.
Disabled adapters are `not-enforced`. Claude path-bearing tools have hook checks;
Codex workspace-write limits writes. Shell reads outside the roots remain
`not-enforced`. Codex tool dispatch has no installed agent-band runtime hook.
The four-value vocabulary has no runner category: `maxRunMinutes` is marked
`not-enforced` by the CLI/hook, with an explicit detail that the external runner
cancels the process group at the deadline. Admission is not a filesystem jail or
an exclusive native skill discovery guarantee. See the CLI capability matrix
and the design spec's Decisions from CLI research.

## Effective skills and filters

Effective skills expose the winning assignment's `origin` scope and nullable
`pinnedVersion`. `excluded` contains resolved assignments rejected by
`allowedSkillIds`, with `reason: "allowedSkillIds"`. At equal specificity the
lowest scope ID, then assignment ID, wins deterministically.
Role and skill assignment scope filters match direct assignments only. Multiple
filters are combined with AND. Audit `involving` matches actor OR target and is
combined with the other filters, including export filters.

## Dashboard

Availability precedence is blocked, concurrency full, budget exhausted, then ok.
Failures are the last ten failed runs ordered by finish time, then run ID.
`tokenBuckets` contains 24 contiguous one-hour intervals ending at the read time,
oldest first, including zero buckets. Intervals include their start and exclude
their end. Usage events are attributed by event timestamp, independently of run
start and finish. Totals include input plus output tokens only, excluding cache
reads and cost. All times are UTC ISO strings.

## Documentation-only project checks

Projects can opt into `docsOnlyChecks` through `POST /projects` and `PATCH /projects/:id`.
The setting is `null` or absent by default, so the existing full `checks` run for every task.
An object enables a reduced check set and accepts `paths` (glob patterns) and `checks` (shell commands).
Omitted fields in that object default to `["**/*.md", "docs/**", "handoff/**"]` and
`["npx prettier --check <changed files>"]`, respectively. Set `docsOnlyChecks: null`
to disable it. A configured setting requires at least one path and one command.

After the task's changes are committed, the server enumerates changed paths between the
merge base SHA and task HEAD. Only if the diff has at least one file and **every** path
matches one of the configured globs will it run the reduced commands. Mixed diffs,
empty diffs, and projects with the setting disabled use the full commands.
In reduced commands, `<changed files>` is replaced with a shell-quoted list of paths
preceded by `--` to avoid argument interpretation, e.g. `-- 'README.md' 'docs/guide.md'`.

`GET /tasks/:id` and `GET /tasks/:id/diff` include `review.checkSet` (`docs` or
`full`) and `review.checkReason` for new reviews. Older reviews can omit both.
The Changes tab shows the selected set and the reason beside the recorded check results.
